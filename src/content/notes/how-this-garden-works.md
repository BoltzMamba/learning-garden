## 核心理念

一篇文章发布之后，知识并没有"完成"。它会在下面这些动作中继续生长：

1. **复习**：有意识地回顾、巩固，而不是"打开页面看了一眼"；
2. **修订**：知识本身发生了有意义的变化，例如纠正错误、补充关键结论；
3. **提问与回答**：把卡住的地方变成显式的问题，再把答案沉淀下来。

## 什么会出现在学习日历上

| 活动类型 | 来源 | 计数规则 |
| --- | --- | --- |
| 发布 | 笔记的 `published` 日期 | 每篇笔记 1 次 |
| 修订 | `src/data/revisions.json` | 每条修订记录 1 次 |
| 复习 | `src/data/reviews.json` | **同一篇笔记同一天只计 1 次** |
| 解答问题 | 公开问题的 `resolvedOn` 日期 | 每个问题 1 次 |

普通的 Git 提交（错别字、格式调整、部署）**不会**被计入学习活动。

## 记录一次复习

复习通过本地命令行完成，不需要手动编辑日历：

```bash
npm run garden -- review
```

同一天对同一篇笔记再次复习，会更新当天已有的记录，而不是新增一条：

```ts
const key = `${review.noteId}@${review.date}`; // 每篇笔记每天唯一
```

## 一点背景：遗忘曲线

复习的想法大致来自艾宾浩斯遗忘曲线。一个常见的简化模型是：

$$
R(t) = e^{-t / S}
$$

其中 $R$ 表示记忆保持率，$t$ 是距离上次学习的时间，$S$ 表示记忆的稳定性。每次有效复习都会让 $S$ 变大，曲线下降得更慢。

这个站点目前只记录复习，并不实现间隔重复的调度算法。
